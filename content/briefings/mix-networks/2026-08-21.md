## The Week in Detail

### Nym × Peach Bitcoin: The First P2P Bitcoin Marketplace on a Mixnet

Peach Bitcoin announced native Nym mixnet integration on **August 17, 2026** (Nym blog post, "The Nym mixnet now protects your Bitcoin trades in Peach"). This is the most significant real-world mixnet adoption event since Edge Wallet's integration in mid-July, and it extends the pattern from wallets to **marketplaces** — an application category where metadata leakage is directly monetizable by adversaries.

**What Peach is**: A Swiss, non-custodial, peer-to-peer Bitcoin marketplace. No registration and no ID where local law permits; open-source code; coins held in 2-of-2 multisignature escrow so Peach cannot move funds unilaterally. It removes the identity layer that centralized exchanges are built on — but, as the announcement correctly notes, no marketplace can remove on its own the *metadata* of transactions: an ISP or network observer can still tie an IP address to every order placed.

**What the integration does**: With the mixnet toggle on, Peach's traffic takes the full five-hop Nym path — entry gateway → three layers of mix nodes → exit gateway — buried in the network's cover noise. Two user-facing controls matter for the threat model:

- **Allowed exit countries**: the user chooses which countries the mixnet may exit through — essential when a payment method or counterparty is region-sensitive. (This is the user-controlled geo-availability first shipped as NymVPN's geo-exclusion; see below.)
- **Test current country**: an in-app verifier showing which exit the connection is actually routing through — making the protection **verifiable from inside the app rather than taken on faith**. Small feature, significant precedent: verifiable exit is exactly the kind of trust-but-check UX anonymity products have historically lacked.

The integration is **free for every Peach user** — Nym's mixnet usage economics are being carried by the network/operator side, not passed to the end user, at least for this flagship integration.

**Why this matters beyond Bitcoin**: Following Edge Wallet (multi-asset wallet, mid-July), this is the second production integration in roughly a month where mixnet routing ships as an **embedded feature inside an existing product** rather than a separate app the user must adopt. Nym's framing — "plug-and-play Layer 0 anonymity network" — is becoming testable: if wallet and marketplace integrations continue at this cadence, the mixnet's anonymity set grows with each integration's user base, which is the only sustainable path for cover-traffic economics. The counterweight is Cao & Green's paper (below): each integration concentrates de-anonymization value in the active set of mixnodes, making the integrity of the node-selection mechanism proportionally more critical.

### The Catch-Up Paper: Cao & Green Show Nym's Reputation System Is Attackable

The most consequential document added to this library this week is also its oldest: **"Analysis and Attacks on the Reputation System of Nym"** (ePrint **2026/101**, Xinmu Alexis Cao and Matthew Green, Johns Hopkins University; published January 21, revised January 25, 2026). It predates the start of this weekly series (June 19) and had not been documented in this library — a significant omission now corrected, because it is the sharpest public security analysis of Nym's incentive machinery in existence.

**Method**: The authors combined three approaches — source-code analysis of the Nym implementation, data collection from Nym mainnet, and network simulations with a custom-built simulator.

**Core findings**:

1. **Framing attack on performance measurement**: The mechanism Nym uses to measure node performance is vulnerable to a form of framing attack in which **a small number of low-stake nodes can damage the score of high-reputation active nodes**. The measurement layer — which decides who stays in the active set — trusts interactions with nodes that can enter cheaply.
2. **Active-set capture**: Via these attacks, a **moderately resourced adversary** (explicitly not a nation-state budget) may gain control of a fraction of Nym Mixnet's active set. The paper notes this condition may enable **connection de-anonymization attacks** — the end-to-end break the whole architecture exists to prevent.
3. **The survivability dilemma**: The paper's framing generalizes beyond Nym: *nodes' reliability measurement in reputation-enhanced networks faces an inherent tension — the entry of low-reputation nodes is required for network survivability (new operators must be able to join), but open entry grants attackers a platform to launch attacks against the network's own scoring system.*

**Why this matters this week specifically**: On August 19, Nym merged PR **#7073** — "add config score penalty for nodes incapable of sending nyx transactions" — a change to the *same reputation-scoring subsystem* the paper attacks. The network's core defense is under active development *and* under documented active-attack pressure. Meanwhile the Directory Contract stack (next section) decentralizes *directory storage and verification*, which addresses who-gates-the-network but **not** the performance-measurement integrity problem — the framing attack lives in the monitoring layer, not the directory layer. These are complementary fixes for different parts of the trust problem, and only one of them currently has a shipped architectural answer.

**Vault cross-currents**: This paper lands on three established threads:

- The **Nym centralization debate** (Aug 14 update; Privacy Guides "privacy theater" thread) — the paper shifts the critique from governance to mechanism: even a perfectly governed network with an attackable scoring layer fails its users.
- The **Kimwolf Sybil incident on I2P** (Feb 2026, ~700,000 hostile nodes; see [I2P](/kb/i2p/)) — both cases demonstrate that open-membership anonymity networks are Sybil battlegrounds, but Cao & Green show the *quiet* version: no flood required, just patient score manipulation.
- The **MOCHA insight** (ePrint 2025/861, covered in [Mix Networks Friday - Global Passive Adversary Defense and Research Frontier](/kb/global-passive-adversary/)) — anonymity-set engineering must be measured empirically, not assumed. Cao & Green extend that discipline from mixnet *parameters* to reputation *mechanisms*.
- The **trust-graph connection** — reputation scoring of infrastructure nodes is structurally the same problem as [WoT trust scoring](/kb/nostr-web-of-trust/) of social accounts: both must resist framing/Sybil while remaining open-entry for survivability. The [Proof of Personhood](/kb/proof-of-personhood/) field exists because this problem has no cheap solution.

**Citation**: Cao, X.A., Green, M. (2026). "Analysis and Attacks on the Reputation System of Nym." IACR ePrint 2026/101. https://eprint.iacr.org/2026/101

### Nym Directory Contract: Decentralizing the Directory with LtHash

The August 14 update documented the centralization critique: a single corporation (Nym Technologies SA) can gate the entire network through credential issuance and directory control. This week the architectural counter-response became visible in the codebase.

**The PR stack** (all open as of Aug 21):

| PR | Title | Role in the stack |
|----|-------|-------------------|
| [#6933](https://github.com/nymtech/nym/pull/6933) | feat: Directory Contract | The CosmWasm contract itself: on-chain source of truth for nym-node configuration |
| [#6948](https://github.com/nymtech/nym/pull/6948) | feat: Directory Client: Attested Anchor | Client-side anchored attestation of directory contents |
| [#6936](https://github.com/nymtech/nym/pull/6936) | feat: Verifiable Directory Contract retrieval | Off-chain retrieval + verification client |
| [#7013](https://github.com/nymtech/nym/pull/7013) | feat: Directory node publishing | Node-side push publishing |

**The architectural flip**: Node-info distribution moves from **per-node HTTP pulls** (a client must fetch config from each node — chokepoint-prone, spoofable, and the operational reason a central directory service exists) to a **push model**: each nym-node pushes its **ed25519-signed configuration** (keyed by `(node_id, label)`) to an on-chain smart contract, and consumers read the directory from chain.

**The verifiability mechanism — LtHash**: An **incremental on-chain LtHash digest over all entries** makes whole-directory retrieval verifiable. LtHash is a homomorphic multiset hash: the digest of a set of entries can be updated additively as entries are added or removed, without recomputing over the whole set — exactly the property an on-chain directory needs, where every state transition is gas-metered. The primitive shipped this week as the standalone **`nym-lthash` crate** (PR #7025, merged Aug 4, released in v2026.16-como): **LtHash16, a 2 KB accumulator, BLAKE3 as the XOF**, generic over the extendable-output function, with add/subtract multiset operations, serialization, and stability validation. It was extracted verbatim from the directory PR stack to merge independently.

**What this does and doesn't solve**:

- **Solves**: The *directory* stops being a corporate chokepoint. Node existence, configuration, and topology become on-chain, signed, and independently verifiable. A coerced or compromised Nym Technologies SA can no longer silently rewrite who the network is — the blockchain is the source of truth. This also strengthens the re-DKG path (PR #7082, "making future re-DKG smoother," opened this week) — distributed key generation events get harder to manipulate when the participant set is contract-published.
- **Doesn't solve**: Where nodes *are* is only half the question. *Which nodes carry traffic* — the active set, selected via staking and performance scoring — remains governed by the reputation machinery that Cao & Green show is framable. On-chain verifiability of the roster does not confer integrity of the measurements that rank the roster.

**Release vehicle**: The contracts and crate landed in **Nym binaries v2026.16-como** (changelog dated Aug 18, GitHub release published Aug 19), which also carries the Como Network Details v2 endpoint type (#7052), BandwidthController background global-data fetching with global-data-aware readiness (#6988), and a TS SDK 0.2.1 patch release with smoke-gate CI fixes (#7079, Aug 20).

**Primary Sources**:
- PR #6933 (Directory Contract): https://github.com/nymtech/nym/pull/6933
- PR #7025 (nym-lthash crate): https://github.com/nymtech/nym/pull/7025
- v2026.16-como release: https://github.com/nymtech/nym/releases/tag/nym-binaries-v2026.16-como

### Research: Verifiable SelfMix — Bulletin-Board Anonymity (ePrint 2026/1617)

A new architecture paper published August 5 (revised Aug 6), **"Verifiable SelfMix"** (ePrint 2026/1617), proposes an anonymity mechanism orthogonal to both mixnets and DC-nets.

**The problem it targets**: placing messages into a **public bulletin-board table** — an append-only, publicly-readable ordered structure — without revealing which user wrote which slot. This is precisely the shape of Nostr relays, blockchain mempools, transparent logs, and public comment systems: anonymity research rarely addresses these directly, defaulting instead to network-layer solutions (Tor/mixnets) that leave *timing* correlation on the table.

**The construction**: VSM separates two concerns:

1. **Unique Number Selection (UNS)** — assigns each user a distinct hidden location in the table. Instantiated via **trusted hardware** or **multi-server plaintext-equivalence tests**.
2. **Secure Mapping of Private Permutation (SMPP)** — places each encrypted message at its assigned location without revealing the user-to-location mapping. Instantiated via **ElGamal**, **Boneh–Goh–Nissim (BGN)**, and a theoretical **FHE** construction.

**The distinctive property**: Because each user learns their own final location, VSM provides **unconditional individual verifiability** after the table is decrypted — a user can check that *their* message landed where it should have, without trusting any server. Anonymity, integrity, and self-verifiability are proven in a static malicious model.

**Costs**: For n users and m slots, the vector-based SMPP constructions require **O(m) ciphertext upload per user** and **O(nm) public aggregation** — heavy; the FHE variant reduces client upload to **Õ(log m)** for fixed-size messages. This is early-stage theory, not a deployable library.

**Vault relevance**: The bulletin-board model is the correct abstraction for the Nostr ecosystem ([WoT](/kb/nostr-web-of-trust/) attestations, NIP-85 reviews) and for any future transparent-log reputation system — and the *individual verifiability* property composes naturally with the trust-graph work in [OpenPGP Web of Trust](/kb/openpgp-web-of-trust/) and [Nostr Web of Trust](/kb/nostr-web-of-trust/). It also connects to [PIR](/kb/private-information-retrieval/) thinking: both fields are converging on "public structure, private access pattern" as the design center.

**Citation**: "Verifiable SelfMix." IACR ePrint 2026/1617 (Aug 5, 2026). https://eprint.iacr.org/2026/1617

### Katzenpost: Commits Resume, and They're All Operational Maturity

Last week's update noted Katzenpost had gone quiet since July 15. That ended August 14–15 with a cluster of merged PRs — and their content is diagnostic of the project's phase:

- **#1092 — server: withdraw from consensus before shutdown**: A shutting-down server now cleanly removes itself from the consensus document rather than disappearing. For a federated mixnet, graceful departure is what preserves anonymity-set honesty: users must not route through nodes that are going away mid-stream.
- **Graceful shutdown abort**: `cmd/server` now aborts the graceful shutdown on a **second SIGINT/SIGTERM** — the standard operator escape hatch for stuck shutdowns, straight out of production-ops playbooks.
- **PKI documentation**: `StopAdvertising` wait/liveness dependencies are now documented in the pki package — API contracts for how a node exits the directory.
- **#1093 — replica: deflake the proxy semaphore scope tests**: test-suite stabilization, the unglamorous work that indicates CI is being taken seriously for long-running development.

No releases (v0.0.99 remains latest tag); the Pigeonhole scattered-storage and QUIC transport tracks from previous updates continue beneath these housekeeping commits. The pattern matches the [Katzenpost](/kb/katzenpost/) characterization in the tracker: research-grade infrastructure being slowly hardened toward federated deployment — now visibly in the operational-hardening phase.
