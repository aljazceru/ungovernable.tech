## The Week in Detail

### HOPR — Piz Palü v5.0.0 Stable Ships Oct 13 + PIX/Curvy Partnership Oct 14 + HOPR API v4.4.0 + HOPR Docs v5.0.0

**[HOPR Piz Palü](https://x.com/hoprnet/status/2110038142598152378)** is the major release that:

1. **"Opens node running to everyone"** — the **Network Registry NFT** model that required an early-access NFT for the prior Dufour/Monte Rosa releases is **discontinued in Piz Palü**, replacing prior boost-NFT mechanisms with a flat-stake model.
2. **"Prepares the network for @Gnosis_VPN launching in Q4 2026"** — Piz Palü is the protocol-layer cut that lands **before** Gnosis VPN (a privacy-first consumer VPN that runs over the HOPR mixnet) goes live.
3. **Restructures cover traffic** — "*Cover traffic has changed to reflect this: incentivized cover traffic*" (the @hoprnet tweet thread). The [Cover Traffic](https://docs.hoprnet.org/core/cover-traffic) docs and the [Tickets and Payment Channels](https://docs.hoprnet.org/core/tickets-and-payment-channels) docs are both tagged **v5.0.0**, meaning the *economic* model is the change, not the protocol primitive.
4. **Dufour migration story** — the HOPR AMA on X (Oct 16) addresses migration from Dufour, including **a new Safe, node module and wxHOPR transfer** (so existing node runners migrate their bonded wxHOPR + bond from a Dufour account/operator-Safe to the Piz Palü structure).

**[HOPR v5 measurement-driven relay selection](https://x.com/hoprnet)** (Oct 13, 11h) — **"HOPR v5 introduces a major change to how nodes select relays. Instead of simply checking who's online, the network now measures how reliably and quickly packets move through it."** This is **the relay-selection algorithm shift that anonset/Monte Rosa-tunable nodes have been waiting for**: a node that lets a malformed packet queue behind its ack-acks scores low, whereas Dufour-era relay selection rewarded any node that simply responded. Operator implications: **nodes need a healthy ack rate, not just uptime**.

**[Curvy Protocol partnership, Oct 14](https://x.com/hoprnet/status/...curvy)** — **"A privacy network can hide your traffic and still leak who paid for it. That leak usually happens on day one, when funds enter the system. We've been working with @Gnosis_VPN and @hoprnet to close it inside PIX."** The technical deep-dive explains how **PIX rewards exit operators for delivering traffic**, while **@0xCurvy keeps those payments unlinkable on-chain** — **the Gnosis-VPN-payment-path is the first consumer-grade use case for PIX payments**.

**[HOPR API v4.4.0](https://github.com/hoprnet/hopr-api/releases)** (Oct 13, 18:39 UTC, release tag `7575071`) ships in lockstep with the protocol — the **hopr-api is the JavaScript library HOPR apps integrate against**, so a stable hoprnet → a stable API.

**[HOPR docs versioning](https://docs.hoprnet.org/)** — Cover Traffic page now **v5.0.0**, Tickets & Payment Channels page now **v5.0.0**. The docs survive the major-version cut, **meaning the documentation surface is itself a stable reference for the v5 model**.

* **HOPR 4.x stable** — *superseded by Piz Palü (v5.0.0)* rather than 4.x being the stable cut. The open-source `release/4.0` branch backports (e.g. #8488 4.0-backport of #8486) remain available for operators still on Dufour.
* **Gnosis VPN launch** — now **concrete Q4 2026** with the PIX/Curvy payment unlinkability concrete.

* **GNO-805 channel-balance incident trilogy** (#8485/#8487/#8486) — *closes last week and is carried into Piz Palü as the relay-selection economic basis*.

### Katzenpost — #1207–#1235 Cluster (Oct 9–14)

W42 extends the **#1206/#1213/#1214 W41 hardening cluster** with **eight more merged security/correctness PRs (Oct 9–11)**, then a **clean Convergence cluster (Oct 12–14)**, then **packaging/release PRs (Oct 14)**. The trajectory is "**harden the protocol → plumb the transport → bump the deps → tag the release**".

#### Oct 9–11 — the W41 backlog merges

* **[#1207](https://github.com/katzenpost/katzenpost/pull/1207) (Oct 9) `server: mix key replay filter, first boot link key, log level, channel gauges`** — **mix keys gain a replay filter** (re-discovery of a previously-seen mix key is rejected rather than re-accepted); first boot generates a **first-boot link key** that wraps the first session; log level to `info` reduces what lands in operator logs (privacy default); **channel gauges** expose per-channel counters via `prometheus`-style metrics.
* **[#1208](https://github.com/katzenpost/katzenpost/pull/1208) (Oct 9) `server, courier: kaetzchen fixes and courier re-dispatch pacing`** — kaetzchen (mixnet-side auto-responder services) drop errors are now gauge-paired; courier re-dispatch is paced (not "as fast as the worker can fire").
* **[#1209](https://github.com/katzenpost/katzenpost/pull/1209) (Oct 9–10) `client: socks5 panic, ARQ jitter, bandwidth estimate, ping per epoch, retryable pigeonhole-not-ready`** — five sub-fixes: **a SOCKS5 client panic that could crash the client when a pending request was reaped**, **ARQ (automatic repeat request) jitter** to spread retransmissions, a **bandwidth estimate** in the client that surfaces for the operator, **ping-per-epoch** (one ping per consensus epoch rather than per request), and **retryable pigeonhole-not-ready** (the client no longer treats "pigeonhole service not yet up" as fatal).
* **[#1210](https://github.com/katzenpost/katzenpost/pull/1210) (Oct 10) `core/pki, authority/voting, server: optional descriptor fields, client notice, service delay`** — **descriptor fields are now optional** (descriptors can omit fields the operator doesn't run); **clients receive a notice** when the PKI publishes a change that affects them; **service delay** is the new server config knob (delay before service starts so the server doesn't accept connections before the PKI considers it "ready").
* **[#1211](https://github.com/katzenpost/katzenpost/pull/1211) (Oct 10–11) `server/cborplugin, courier: host-chosen plugin socket, host geometry, plugin parameters`** — the **cborplugin transport layer** now supports **host-chosen plugin sockets** (the host, not the plugin, picks the socket path), **host-chosen geometry** (the host, not the plugin, picks the Sphinx-packet geometry), **plugin parameters** (the host can configure the plugin at spawn time). This is the **protocol-level plumbing** that lets one katzenpost host run plugin servers with different parameter profiles.
* **[#1217](https://github.com/katzenpost/katzenpost/pull/1217) (Oct 11) `docker, quic, courier: pick the testnet transport, keep QUIC links alive, serve a cached read success`** — the **testnet transport is selectable from the docker image**; **QUIC keepalives** keep idle QUIC links from being silently dropped; **cached read success** is the new courier endpoint (a reader can hit a cache and fall back to the chain).
* **[#1220](https://github.com/katzenpost/katzenpost/pull/1220) (Oct 11) `authority: bind descriptor uploads to the session link key; per-identity slots for pinned nodes`** — **authority-side descriptor uploads are now bound to the session's link key** (an upload that comes in on one session can't be re-played on another) — **per-identity slots for pinned nodes** (each pinned node gets its own slot, so one node can't fill another's quota).
* **[#1221](https://github.com/katzenpost/katzenpost/pull/1221) (Oct 11) `kpclientd: systemd socket activation`** — the **kpclientd (Katzenpost client daemon)** now supports **systemd socket activation** — meaning systemd can hold the listening socket and `kpclientd` can be brought up lazily when the first connection arrives, then torn down when idle. **This is the "run-anywhere mixnet" hook that operators have been asking for** since [Mix Networks 2026 Research and Deployment Tracker](/kb/mix-networks-tracker/) noted the kpclientd bottleneck in late W41.

#### Oct 12–14 — Convergence Cluster

* **[#1222](https://github.com/katzenpost/katzenpost/pull/1222) (Oct 11–12) `server/service: halt predelay before worker, drain readyCh on shutdown, and guard releaseDelayed`** — server starts the **predelay timer before the worker goroutine starts** so a slow worker doesn't get free admission; on shutdown **`readyCh` is drained** so a worker that received "stop" doesn't miss the close; **releaseDelayed guard** prevents a delayed release from being released twice.
* **[#1223](https://github.com/katzenpost/katzenpost/pull/1223) (Oct 12) `server/service: halt predelay before worker, drain readyCh on shutdown, and guard releaseDelayed`** (same as #1222; separate small PR or rebase — to be clarified). **[#1224](https://github.com/katzenpost/katzenpost/pull/1224) (Oct 12) `go.mod, ci: update go to 1.26.9, x/net to v0.61.0, and check-latest Go`** — **go.mod pins go 1.26.9** (the chain's first 1.26.9-stable pin), **golang.org/x/net to v0.61.0** (off the v0.51.0 of late W41), and **CI checks for the latest Go** at build time.
* **[#1225](https://github.com/katzenpost/katzenpost/pull/1225) (Oct 12) `docker, ci, genconfig: match namenlos with KYBER768-X25519 on the wire`** — **Kyber768-X25519** is the wire-level hybrid that the "namenlos" (nameless) configuration now advertises in CI; mismatches between CI config and genconfig are resolved.
