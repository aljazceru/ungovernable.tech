Definitions

Glossary

124 short definitions for terms used across the library. Terms link to the entries that cover them in depth.

ABCDEFGHIKLMNOPRSTVWXYZ

A

AEAD

Authenticated Encryption with Associated Data. Modern symmetric mode (AES-GCM, ChaCha20-Poly1305) that combines confidentiality and integrity in one primitive.

Alice / Bob / Eve / Mallory

Standard cryptographic example names. Alice and Bob are honest parties; Eve is a passive eavesdropper; Mallory is an active attacker.

Anonymity set

The possible subjects an observer cannot distinguish as responsible for an action, such as sending a message. The set depends on the observer's information and can change over time; it is not automatically every user of a network. See Pfitzmann and Hansen's terminology paper.

See Metadata Resistance, Tor, Mix Networks
Attestation

Cryptographic proof of the identity, configuration, and code hash of a piece of software running inside a TEE. Anchored in the hardware vendor's signing keys (Intel DCAP, AMD KDS, NVIDIA NRAS). See Attestation-Architecture.

See Remote Attestation Architecture
Attested TLS

A TLS connection where the server's keypair is generated inside an enclave and the attestation report is bound to the TLS certificate (or pinned in a Channel Binding). Lets a client verify it is talking to specific code on specific hardware, not just any holder of the cert.

B

BBS+

Pairing-based signature scheme that supports selective disclosure of attributes and zero-knowledge proofs of possession. Foundation of W3C Verifiable Credentials with privacy.

Bitchat

Phone-only Bluetooth-LE mesh messenger from Permissionlesstech, with a Nostr fallback for global reach. Up to seven hops over BLE, Noise-encrypted, no accounts. Geohash-based location channels on the Nostr side. See Bitchat.

See Bitchat
Blinding / Blind signature

Cryptographic technique where a signer signs a message it cannot read. Used by Chaumian eCash, Cashu, and parts of mixnet payment schemes.

Bridge

A Tor relay omitted from the public relay directory, providing an alternative entry when known relays are blocked. See pluggable transports and bridges and Tor's relay guide.

See Tor, Pluggable transports and bridges
Bulletproofs

Short, non-interactive zero-knowledge range proofs that need no trusted setup. Used in Monero (transaction amounts) and various confidential-transaction protocols.

Bundle Protocol

A protocol for carrying application data across networks with intermittent connectivity. Version 7 is specified in RFC 9171; custody transfer is outside its base protocol. See delay-tolerant networking.

See Delay-tolerant networking, Off-Grid Networks

C

CCIP-Read (EIP-3668)

Pattern that lets ENS resolvers serve names from off-chain backends with cryptographic proofs.

Chaumian eCash

Bearer token system using blind signatures (Chaum, 1983). Modern implementations: Cashu (Bitcoin/Lightning), GNU Taler.

CoCo (Confidential Containers)

CNCF project bringing confidential computing to Kubernetes via Kata plus TEE-backed VMs and a Trustee KBS. See Confidential-Containers.

See Confidential Containers (CoCo)
Confidential Computing

Hardware-backed protection of data during computation, complementing at-rest and in-transit encryption.

Content addressing

Identifying data by an identifier derived from its contents rather than its server location. In IPFS, changing content changes its CID; the identifier does not itself keep a copy available. IPFS content addressing.

See IPFS and Filecoin, BitTorrent for Archive Distribution, Blossom: Blob Storage on Nostr
Cover traffic

Dummy packets sent on a schedule to hide whether real traffic is flowing. Core to mixnet metadata defense.

CRR (Continual Re-Randomization)

Property of mix networks where each hop re-encrypts (or re-blinds) the packet so the bit pattern changes between links.

Cryptographic inventory

A maintained record of where systems depend on cryptography and which implementations, owners and suppliers must participate in a migration. See the inventory workflow and CISA, NSA and NIST guidance.

See Build a post-quantum cryptographic inventory, Post-Quantum Cryptography

D

DCAP (Data Center Attestation Primitives)

Intel's open attestation infrastructure for SGX/TDX, replacing the EPID-based Attestation Service for production use.

Decentralized storage

Storage architecture where integrity, persistence, or retrieval is distributed across independent operators rather than a single cloud account. Includes content-addressed systems (IPFS), paid storage markets (Filecoin, Sia), archival networks (Arweave), and app-specific blob layers (Blossom).

Deep packet inspection (DPI)

Inspection of network traffic to recognise protocols from packet contents or patterns, including when the carried data is encrypted. Censors can use it to identify and block tunnels. See WireGuard and Psiphon's protocol explanation.

See WireGuard, Psiphon, Pluggable transports and bridges
DHT (Distributed Hash Table)

Key-value store spread across many nodes (Kademlia, Mainline). Used for peer discovery, BitTorrent trackers, PKARR record storage.

DID (Decentralized Identifier)

W3C URI scheme did:method:id resolving to a DID Document with public keys and service endpoints. Methods: did:key, did:web, did:ion, did:plc, did:peer, did:ens.

Double Ratchet

Per-message key rotation algorithm in Signal/MLS that combines a Diffie-Hellman ratchet with a symmetric KDF chain to deliver forward secrecy and post-compromise security.

DTN (Delay-Tolerant Network)

Networking architecture (RFC 4838) for intermittent or high-latency links. Uses store-carry-forward bundles. Used in mesh, satellite, and disconnected operation.

E

Ed25519

EdDSA signature scheme over Curve25519. Compact, fast, deterministic; widely used in Tor v3, SSH, age, Pubky/PKARR, Yggdrasil, MLS BasicCredentials. Note: Nostr uses Schnorr over secp256k1 (BIP-340), not Ed25519.

EIP-7702 / EIP-4337

Ethereum account-abstraction proposals enabling smart-contract behavior on EOAs and bundled UserOps respectively.

Enclave

Hardware-isolated region of memory and execution; the umbrella term for SGX enclaves, SEV-SNP VMs, TDX TDs, and similar.

Erasure coding

Encoding data into N shares so that any k valid shares can reconstruct it. Tahoe-LAFS uses this to tolerate missing shares; availability still depends on share placement and retention. Architecture.

See Tahoe-LAFS, Choosing Decentralized Storage

F

FHE (Fully Homomorphic Encryption)

Encryption that supports arbitrary computation on ciphertexts. See Overview - Fully Homomorphic Encryption.

See Fully Homomorphic Encryption
fhEVM

Ethereum-compatible EVM that operates on FHE ciphertexts. Zama's flagship.

FIPS

Free Internetworking Peering System. Mesh routing protocol that uses Nostr secp256k1 keypairs as native node identities. Multi-transport (UDP, TCP, Ethernet, Tor, BLE), Noise-encrypted hop-to-hop and end-to-end. See FIPS.

See FIPS (Free Internetworking Peering System)
Forward Secrecy

Property where compromising long-term keys does not compromise past session keys. Achieved via ephemeral DH (TLS 1.3, Signal X3DH/PQXDH).

FROST

Flexible Round-Optimized Schnorr Threshold signatures (Komlo & Goldberg 2020; standardized as RFC 9591 in 2024). Used for threshold Bitcoin/Nostr key custody.

G

Garlic Routing

I2P's variant of onion routing where one packet ("garlic clove bundle") may contain multiple inner messages with different destinations.

Geohash

Hierarchical encoding of geographic coordinates as a base32 string where shorter prefixes denote larger areas. Used by Bitchat location channels; precision selects neighborhood, city, or region scope.

See Bitchat
GNS (GNU Name System)

Privacy-preserving petname-based hierarchical naming, RFC 9498.

Groth16

Pairing-based zk-SNARK with constant-size proofs (~128-200 bytes depending on curve: 2×G1 + 1×G2 over BN254 / BLS12-381) and per-circuit trusted setup. Used by Zcash Sapling, Tornado Cash, Semaphore.

Grover's algorithm

Quantum search algorithm giving a √N speedup over classical brute force. Effectively halves symmetric key strength. AES-256 retains a 128-bit security margin against it.

H

Halo2

PLONK-family proof system from Electric Coin Co.; recursive composition without a fresh trusted setup per circuit. Used in Zcash Orchard.

Handshake (HNS)

Blockchain-based replacement for the DNS root zone, with permissionless TLD ownership.

Harvest now, decrypt later

Adversary records encrypted traffic today expecting to decrypt it once a quantum computer exists. The motivation for migrating long-secrecy traffic to post-quantum KEMs now.

Hybrid KEM

Composition of a classical KEM (such as X25519) and a post-quantum KEM (such as ML-KEM-768) where the shared secret is the KDF of both halves. Currently deployed in TLS 1.3, SSH, Signal PQXDH, iMessage PQ3.

I

I2P (Invisible Internet Project)

Anonymous overlay network using garlic routing and unidirectional tunnels.

IETF

Internet Engineering Task Force; the body that publishes RFCs.

Ion / did:ion

DIF DID method anchored on Bitcoin via Sidetree (a Layer-2 ledger).

IPFS CID

Content Identifier used by IPFS to name data by cryptographic hash plus codec metadata. A CID proves byte integrity, while availability depends on pinning or storage deals.

K

Kademlia

DHT algorithm using XOR distance for routing. The basis of Mainline DHT, IPFS, libp2p Kad-DHT.

KBS (Key Broker Service)

Component in CoCo Trustee that releases secrets to enclaves only on a valid attestation.

KDS (Key Distribution Service)

AMD's attestation backend: serves VCEK / VLEK certificates that endorse SEV-SNP attestation reports.

KEM (Key Encapsulation Mechanism)

Primitive that produces an encapsulated symmetric key for a recipient public key. Replaces Diffie-Hellman in post-quantum protocols.

Key Escrow

Third-party holding of decryption keys. Contradicts sovereignty; historically pushed by states (Clipper chip).

L

Lattice cryptography

Hardness assumptions based on lattice problems (LWE, Ring-LWE, Module-LWE, NTRU). Foundation of FHE and most NIST PQC KEM/signature standards (ML-KEM, ML-DSA, FN-DSA); SLH-DSA is the hash-based exception.

Lightning Network

Layer 2 Bitcoin protocol of bidirectional payment channels with hash-time-locked routed payments. See Lightning Network Deep Dive.

See Lightning Network
Loopix

Continuous-time mix network design (Piotrowska et al., 2017): Poisson-mixing with cover traffic. Foundation of Nym and Katzenpost.

LoRa

Low-power long-range radio modulation (sub-GHz ISM bands) used by Meshtastic, MeshCore and other off-grid networks.

See Meshtastic, MeshCore
LWE (Learning With Errors)

Lattice problem on which most modern lattice crypto rests.

M

Mainline DHT

The BitTorrent DHT, around 10 million nodes worldwide. Used by PKARR/Pubky for record publication.

Marmot Protocol

Specification for using MLS (RFC 9420) over Nostr's identity and relay infrastructure for forward-secret, post-compromise-secure, scalable group messaging. KeyPackages (kind 30443), gift-wrapped Welcomes (kind 444 inside 1059), encrypted group events (kind 445). See Marmot Protocol.

See Marmot: MLS over Nostr
mDL (Mobile Driver's License, ISO 18013-5)

Standard for mobile credentials with selective disclosure. Deployed in several US states and the EU Digital Wallet.

MEV (Maximal Extractable Value)

Value extracted from transaction ordering by validators, builders, and searchers. Originally "Miner Extractable Value"; renamed in 2022 to cover non-miner extractors.

Mixnet

Network that batches, reorders, and re-encrypts traffic across multiple hops to hide who-talks-to-whom from a global observer. See Overview - Mix Networks.

See Mix Networks
ML-DSA (FIPS 204)

Module-LWE signature scheme based on Dilithium. Replaces ECDSA / RSA-PSS for post-quantum signatures.

ML-KEM (FIPS 203)

Module-LWE key encapsulation based on Kyber. Replaces ECDH / RSA-KEM for post-quantum key exchange.

MLS (Messaging Layer Security, RFC 9420)

IETF standard for group E2EE with continuous group key agreement (TreeKEM). Used in Wire and Cisco Webex; Matrix MLS profile in development.

MPC (Multi-Party Computation)

Cryptographic primitive where parties jointly compute a function over their private inputs without revealing them. Honest-majority and dishonest-majority variants exist.

MRENCLAVE / MRSIGNER

SGX measurements: hash of the enclave's initial code/data (MRENCLAVE) and the signing identity (MRSIGNER). Used in attestation policies.

N

Namecoin

Earliest functional blockchain naming system (2011), merged-mined with Bitcoin. .bit TLD.

NIP-05 / NIP-44 / NIP-17

Nostr Implementation Possibilities. NIP-05: human-readable user@domain identifiers via .well-known/nostr.json; NIP-44: versioned DM payload format (ChaCha20 + HMAC-SHA256, conversation key from secp256k1 ECDH); NIP-17: gift-wrapped DMs with metadata protection (combines NIP-44 and NIP-59).

Nostr

Notes and Other Stuff Transmitted by Relays. Pubkey-rooted social protocol; events signed by Schnorr signatures over secp256k1 (BIP-340), served by relays. See Nostr and Nostr Deep Dive.

See Nostr as an Identity Layer, Nostr: The Protocol
NRAS (NVIDIA Remote Attestation Service)

Attestation backend for H100/H200/Blackwell confidential computing.

O

Offline attenuation

Adding restrictions to an authorization token without contacting its issuer. Biscuit uses signed blocks and scoped policy checks so an appended block can reduce authority. See Biscuit and its introduction.

See Biscuit authorization tokens, Verifiable Credentials
Onion routing

Layered encryption such that each relay can peel one layer revealing only the next hop. Tor is the canonical implementation.

OPRF (Oblivious Pseudo-Random Function)

Two-party protocol where the client gets f_k(x) without learning k and the server does not learn x. Used in PIR, password-authenticated key exchange, and private set intersection.

ORAM (Oblivious RAM)

Technique that hides memory access patterns from an observer who can see which addresses are touched.

Overlay network

Logical network running on top of an existing underlay (Yggdrasil, cjdns, Tor, I2P).

P

Payjoin (BIP-78)

Two-party CoinJoin variant where the receiver contributes inputs, breaking the common-input-ownership heuristic.

PCC (Private Cloud Compute)

Apple's confidential AI inference platform (announced 2024). Combines Secure Enclave, code transparency log, and stateless attested servers.

Petname

Local nickname for a globally-unique cryptographic identifier (Stiegler's petname system; Zooko's triangle resolution).

Pinning

Protecting IPFS data from garbage collection on a node. A pin is a local retention choice, not a guarantee that another node will keep the data or stay online. IPFS persistence documentation.

See IPFS and Filecoin, IPNS and DNSLink, Choosing Decentralized Storage
PIR (Private Information Retrieval)

Protocol that lets a client retrieve record i from a database while the server learns nothing about i. See Overview - Private Information Retrieval.

See Private Information Retrieval
PKARR

Public-Key-Addressable Resource Records over Mainline DHT. Names are Ed25519 keys; records are signed and stored under the keyhash.

Pluggable transport

A transport layer that changes how a connection looks on the network to make blocking harder. Tor documents obfs4, Snowflake, meek and WebTunnel in its circumvention guide. Compare them in pluggable transports and bridges.

See Pluggable transports and bridges, Tor
Post-compromise security

Recovery of confidentiality for future messages after an attacker loses access and honest participants introduce fresh secret key material. It does not repair an ongoing endpoint compromise or erase previously exposed messages. See RFC 9420.

See The Signal Protocol, MLS (RFC 9420) and Wire, XMPP with OMEMO
PoW / PoS

Proof of Work / Proof of Stake. Sybil-resistance mechanisms for permissionless consensus.

PQC (Post-Quantum Cryptography)

Cryptography secure against polynomial-time quantum adversaries. See Overview - Post-Quantum Cryptography.

See Post-Quantum Cryptography
PQXDH

Post-quantum extended X3DH; the hybrid (X25519 + ML-KEM-1024) key agreement used by Signal since 2023.

Pseudonymity

Being identified by a pseudonym. Reusing it can link activities even when a personal name is unknown; separate pseudonyms can reduce linkage across contexts. See RFC 6973 and identity and pseudonymity.

See Identity and Pseudonymity, Metadata Resistance
Pubky

PKARR-based identity and naming system from Synonym. Adds a homeserver data plane (HTTP-fetched signed user data) and pkdns for DNS bridging. Reference social app: Pubky.app. See Pubky.

See Pubky

R

Ratchet

A keying scheme that derives new keys irreversibly forward, providing forward secrecy. Symmetric ratchet: KDF chain. DH ratchet: Diffie-Hellman re-key per round-trip.

RATS (Remote ATtestation procedureS)

IETF working group and architecture (RFC 9334) for remote attestation. Defines the Attester / Verifier / Relying-Party roles used across CC ecosystems.

Reticulum

Markqvist's encrypted-by-default mesh networking stack with cryptographic destinations. Runs over LoRa, packet radio, TCP, serial. See Reticulum.

See Reticulum
Reunion

Anonymous contact-establishment protocol over the Katzenpost mixnet. Lets two parties find each other without prior knowledge of network addresses.

Ring-LWE

Variant of LWE on polynomial rings. Smaller keys and faster ops than plain LWE.

S

Schnorr signature

Linear, aggregatable signature scheme. Bitcoin Taproot uses Schnorr/BIP340.

SD-JWT (RFC 9901, 2025)

Selective Disclosure JWT. JWT-based credential format where each claim is committed via a salted hash; the holder discloses the claims they choose by revealing the corresponding hash preimages. Standardized as RFC 9901 in November 2025.

SEV-SNP

AMD Secure Encrypted Virtualization with Secure Nested Paging. VM-level TEE with integrity protection. See TEE-Technologies-Deep-Dive.

See TEE Technologies: SGX, TDX, SEV-SNP and Friends
SGX (Software Guard Extensions)

Intel's per-process TEE (2015–). Powerful but punctuated by side-channel breaks; legacy for new workloads.

Sphinx packet

Format for fixed-size, layered-encrypted mixnet packets that hide path length and per-hop processing.

STARK

Scalable Transparent Argument of Knowledge. Hash-based, no trusted setup, post-quantum candidate; large proofs but fast verifier.

Steganography

Hiding data within other data (messages in images, traffic shaped to look like benign traffic).

Sybil attack

One participant presents multiple identities to gain influence that a system intended to distribute among independent participants. See Douceur's original paper and proof of personhood.

See Proof of Personhood and Sybil Resistance, Webs of Trust
Sybil resistance

Measures that limit the influence one participant can gain through multiple identities. The assumption matters: Douceur's analysis examines identity certification and the limits of resource-based tests. A membership proof alone does not establish one identity per person.

See Proof of Personhood and Sybil Resistance, Semaphore

T

Taproot (BIP-340/341/342)

Bitcoin upgrade (2021) introducing Schnorr signatures and MAST script trees; basis for sub-second-cost cooperative-spend privacy.

TCB (Trusted Computing Base)

The set of hardware/firmware/software a security claim relies on. Smaller TCB means smaller attack surface. TCB versions appear in attestation reports.

TDX (Trust Domain Extensions)

Intel's VM-level TEE (2022–).

TEE (Trusted Execution Environment)

Hardware mechanism for isolated execution. Umbrella term covering SGX, TDX, SEV-SNP, Arm CCA, IBM SE.

Threshold signature

Signature where any t of n parties can sign; fewer than t cannot. FROST (Schnorr), GG20 (ECDSA), Pedersen DKG.

TOR / Tor (The Onion Router)

Low-latency onion-routing anonymity network. Three-hop default circuits; v3 hidden services.

Trustee

CoCo's KBS implementation; gates secret release on attestation policy.

V

VC (Verifiable Credential, W3C)

Signed JSON-LD or JWT structure asserting claims about a subject. Issuer, Holder, Verifier model.

VCEK / VLEK

AMD chip-bound (VCEK) and platform-bound (VLEK) endorsement keys signed by KDS, used to verify SEV-SNP attestation reports.

vFHE (Verifiable FHE)

FHE composed with a SNARK over the homomorphic circuit so the decryptor can verify the server computed the function honestly.

W

WireGuard

Modern VPN protocol; minimal cryptographic core (Curve25519, ChaCha20-Poly1305, BLAKE2s). Influences Yggdrasil, Tailscale, Mullvad.

WoT (Web of Trust)

Peer-attestation trust model: OpenPGP and Nostr social-graph variants. See Overview - Web of Trust.

See Webs of Trust

X

X25519

Diffie-Hellman over Curve25519. Default ECDH primitive in TLS 1.3, Signal, WireGuard.

X3DH

Extended Triple Diffie-Hellman key agreement (Signal, 2016). Replaced by PQXDH in production.

Y

Yggdrasil

Encrypted IPv6 mesh overlay; routing by cryptographic identity.

Z

Zama

Commercial FHE company; ships Concrete (TFHE) and fhEVM.

ZK Proof (Zero-Knowledge Proof)

Prove a statement true without revealing why.

ZK-SNARK

Zero-Knowledge Succinct Non-interactive ARgument of Knowledge.

ZK-STARK

Zero-Knowledge Scalable Transparent ARgument of Knowledge.

Zooko's triangle

Hypothesis that names cannot be simultaneously human-meaningful, decentralized, and globally unique. Petnames plus cryptographic IDs (for example Pubky, ENS) are partial resolutions.

Cypherpunks write code.

— Eric Hughes, A Cypherpunk's Manifesto, 1993
