# ungovernable.tech

A reference library of the technologies people use to free themselves:
anonymity networks, censorship circumvention, secure messaging, off-grid
mesh, sovereign naming, identity, financial sovereignty, decentralized
storage and compute, confidential computing, privacy-enhancing
cryptography, zero-knowledge, post-quantum keys, and the devices and
operational security that hold it together.

It is a non-exhaustive list of building blocks for a better, more
decentralized internet that enables freedom from surveillance capitalism
and governmental overreach — focused on the topics that do not get enough
attention, and honest about which of them are ready and which are not.
Every entry says what it protects against, what it trusts, and how ready
it is. No trackers, no cookies, no third-party requests.

For any suggestions or comments submit a
[PR/open an issue](https://github.com/aljazceru/ungovernable.tech) or send
smoke signals over nostr to [aljaz@nostr.si](https://nostr.at/aljaz@nostr.si).

## Layout

    content/
      pillars.yml            the 14 pillars (key, name, question, intro)
      entries/*.md           one file per entry or guide (YAML frontmatter + markdown)
      briefings/<series>/    dated weekly research briefings
      paths.yml              persona learning paths (optional)
      glossary.yml           glossary terms (generated by import_vault)
      sources.md             shared bibliography (generated by import_vault)
      vault_fixes.yml        persistent corrections to vault entries, keyed by slug
      vault_aux_fixes.yml    corrections to generated briefings and bibliography
      directory/*.yml        curated outbound links per pillar (generated by import_directory)
      directory/overrides.yml  editorial fixes to the legacy link lists
      pages/*.md             about.md, method.md (optional; built-in text otherwise)
    scripts/
      vault_map.yml          editorial map: research vault -> slugs, types, readiness
      import_vault.py        vault -> content/ (entries, briefings, glossary, sources)
      import_directory.py    legacy link pages (branch main) -> content/directory/
      build.py               renders the whole site into public/
      serve.py               stdlib production server (gzip, CSP, 301s for stubs)
      site_check.py          crawl public/: broken links, sitemap, head contract
      fonts/                 TTFs used to render the OG images (OFL 1.1)
    templates/               Jinja2 templates
    assets/                  css, js, vendored fonts (OFL 1.1)
    legacy/                  the original GitHub Pages link lists (input to import_directory)
    deploy/                  systemd unit + deploy script
    tests/                   pytest quality bar

## Content schema

Entry frontmatter (`content/entries/<slug>.md`):

```yaml
title: "Tor"                  # H1 / display name
slug: tor                     # URL slug, unique
type: deep-dive               # explainer | deep-dive | comparison | threat-model | guide | reference | map | research-note
pillars: [anonymity, circumvention]   # primary first; keys from pillars.yml
readiness: battle-tested      # optional: battle-tested | usable | experimental | research | historical | cautionary
description: "..."            # meta description, 110-160 chars, ends with a full stop
dek: "..."                    # one-sentence subtitle under the H1
updated: 2026-09-04
created: 2026-04-25
origin: vault                 # vault (generated; re-import overwrites) | original (hand-written; never overwritten)
source: "08-Mix-Networks/Tor.md"   # vault origin only
aliases: [Onion Routing]      # optional
tags: [tor, onion-routing]    # optional
related: [i2p, nym]           # optional hand-curated related slugs
level: beginner               # optional, guides: beginner | intermediate | advanced
time: "30 minutes"            # optional, guides
```

Entries with `type: guide` are published under `/guides/<slug>/`; everything
else under `/kb/<slug>/`. Briefings live under
`/briefings/<series>/<yyyy-mm-dd>/` and are dated records, not maintained
references.

## Commands

```sh
# import the research vault (read-only input) into content/
python3 scripts/import_vault.py --vault /path/to/ungovernable-tech-vault

# regenerate the curated link directory from the legacy pages on branch main
python3 scripts/import_directory.py

# build the site into public/ (wiped and rebuilt; deterministic)
python3 scripts/build.py

# verify: broken links, sitemap exactness, head contract, duplicate titles
python3 scripts/site_check.py

# local production-like server (gzip, CSP, legacy 301s) on :8000
python3 scripts/serve.py --port 8000

# the full quality bar
python3 -m pytest -q
```

Both importers and the build are idempotent: running twice produces no
diff. Hand-written pages (`origin: original`) are never overwritten or
deleted by the importer.

Keep corrections to generated entries in `content/vault_fixes.yml`:

```yaml
entry-slug:
  replace:
    - old: "Exact text in the generated body"
      new: "Replacement text"
  sources:
    - title: "OpenSSH post-quantum cryptography"
      url: "https://www.openssh.com/pq.html"
  updated: 2026-10-25
```

All three fields are optional. Replacements run in order on freshly generated
markdown and also replace matching text in `dek` and `description`. An unmatched
`old` string, an unknown slug, or a fix targeting an original entry aborts the
import with a warning before any files are written. `sources` replaces the body
of a `## Primary sources` or `## Sources` section, or appends a new section.
Existing appended text, related links and glossary hooks remain in effect.
`content/vault_aux_fixes.yml` uses the same records, keyed by generated output
path, for briefings and the shared bibliography. Never edit the source vault.

## Editorial rules

- **Primary sources first**: specifications, RFCs, FIPS, papers and
  canonical repositories — not press releases. The [readiness
  scale](https://ungovernable.tech/method/) (battle-tested → cautionary)
  is on every technology entry.
- **Experimental is not production.** The meter separates them; treat
  anything below *usable* as something to watch, not depend on.
- **Name the trust model.** A system is only as sovereign as its weakest
  trusted party; that party is named in the entry.
- **No trackers.** The site is static, self-contained and serves its own
  fonts. Nothing phones home.
- Entries are compiled from a dated research log; authorship and process
  notes stay in the repo, not on the site.

## Deploy

On the server (see `deploy/ungovernable-site.service`):

```sh
git -C /home/exedev/ungovernable.tech fetch
git -C /home/exedev/ungovernable.tech checkout <branch>
git -C /home/exedev/ungovernable.tech reset --hard origin/<branch>
python3 scripts/build.py
sudo systemctl restart ungovernable-site
```

or run `deploy/deploy.sh <branch>`. TLS terminates at the edge proxy; the
server itself is plain HTTP on localhost:8000 with HSTS deliberately
omitted.
