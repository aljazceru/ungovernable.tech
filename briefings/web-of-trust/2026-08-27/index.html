Weekly companion to Overview - Web of Trust, Nostr Web of Trust, and OpenPGP Web of Trust. Covers developments since the August 20, 2026 update. Headline themes: (1) the re-measurement last week's closer asked for is in, and the flat line is now a plateau — zero new kind:10203 publishers in the nine days since Aug 18; the launch cohort remains the entire user base; (2) npm downloads for the PQ stack collapsed to ambient (@nostr-wot/pq: 282 → 26/week); (3) the nostr-wot organization has visibly pivoted: the main repo shipped a daily AI-operated newsroom — thirty-plus commits this week building an automated Nostr-ecosystem publication with RSS/JSON feeds, a Google News sitemap, a six-month archive retrofill, a committed editorial playbook, a run log, and a PAUSE-file kill switch — while the extension repo has been frozen since Aug 19; (4) upstream is unchanged: NIPs PR #2434 untouched since Aug 11, and the NIPs repo merged three non-PQ changes (NIP-A3 payto, NIP-30 emoji on kind 1111, NIP-22 kind-1 replies); (5) the self-hostable WoT layer shows life exactly where last week's analysis predicted: fiatjaf/pyramid pushed its first commit since June and bitvora's wot.nostr.net answers HTTP 200, while hosted providers keep dying — nostr.band unreachable from a second vantage point, wot.klabo.world still NXDOMAIN; (6) GnuPG at 971★ shipped gpgsm fixes, Sequoia landed SLH-DSA documentation work on main. The ungovernable takeaway: the PQ shadow protocol has entered maintenance mode at 24 identities, and the energy behind it has moved to something new — an autonomously published news operation whose editorial governance lives in a git repo. One org, two experiments in doing things without permission: an unratified NIP nobody blocks, and a newsroom with no editor.

  • npm collapse: @nostr-wot/pq at 26 downloads/week (was 282 last week), SDK at 59/week (was 235). The launch-spike decay is complete; both packages now sit at ambient-dependency levels. No new releases — pq still v0.2.2, SDK still v1.0.1 (both Aug 16).

Atop it runs a daily newsroom agent governed by docs/newsroom/playbook.md (7.5 KB) with a run log and a kill switch.
  • The playbook's sourcing rule was born from a fabrication incident. "During the retrofill, a fetched 'newsletter' page returned content describing a private repository in terms lifted from internal notes, for a project with no public footprint. Fabricated pages cannot be told apart from real ones here. Structured API responses cross-check; prose does not." The agent is therefore restricted to GitHub API responses only — nips PRs/commits, tagged releases of major clients/relays, diffs. No web search, no prose pages.
  • Run log semantics worth stealing: one line per run including runs that published nothing — "skipped is a normal, healthy outcome: it records that the agent ran, looked, and found nothing that cleared the bar. An absence of lines means the agent did not run at all, which is a different problem entirely." Aug 24: published (NIP-22 story, 2 sources). Aug 25: published (NIP-30 emoji, 1 source). Aug 26: skipped, with the considered-and-rejected candidates logged inline (#2448, #2358, Amethyst v1.14.0).
  • Kill switch: if content/news/PAUSE exists, the agent stops, publishes nothing, logs paused, exits. "Changing what counts as news, or how it is written, is a commit to this file. Do not encode editorial rules in the schedule, where they cannot be reviewed or reverted."
  • Extension frozen: nostr-wot-extension last pushed Aug 19 (v0.5.2); zero commits since; 7 open issues. The SDK repo also quiet (last push Aug 17). The oracle remains dormant (now 12 weeks, since Jun 4).
  • Upstream unchanged: NIPs PR #2434 open, 1 comment (fiatjaf's link), last updated Aug 11. nostr-tools #541 closed. NIPs repo (3,090★) merged: NIP-A3 payto: Payment Targets (RFC-8905) (#2119, Aug 26), kind 1111 custom-emoji into NIP-30 (#2448, Aug 25), kind-1111-replies-to-kind-1 for NIP-22 (#2250/#2358, Aug 24). Nothing PQ.
  • WoT infrastructure — the bifurcation sharpens: pyramid (73★) revived with "Add restricted prefix when not a member" (Aug 21, first push since June); wot.nostr.net (bitvora wot-relay deployment) verified HTTP 200; nostr.band unreachable from a second vantage point (ConnectTimeout, DNS resolves) — two consecutive failures, now treated as dead for operational purposes; wot.klabo.world still NXDOMAIN; nostr-relay-tray unchanged (108★, last push Feb 2).

No TOFU deprecation, no release. Sequoia: SLH-DSA documentation improvements (Aug 24) plus dependency updates — PQ-visible work on main, still no full PQ landing.

Freedom-tech takeaway: Last week's strategic read — treat PQ Nostr as an exercisable option, not dependable infrastructure — is now the measured reality: 24 identities, zero growth, ambient downloads, upstream frozen, extension frozen. But the week's genuinely new artifact is the newsroom, and it matters beyond Nostr: it is a working, publicly observable instance of autonomous publishing with in-repo editorial governance — sourcing rules written down before the run, a kill switch any human can trip with a file, a run log that distinguishes "nothing worth publishing" from "agent dead," and a documented fabrication incident that produced a hardened sourcing policy. For the Daemon network this is a design pattern to copy: the playbook's three choices (structured-API-only sourcing, log-every-run-including-no-ops, kill-switch-as-file) are exactly the controls an autonomously operated publication needs before it can be trusted with an audience. The irony writes itself: the project that could not get its protocol ratified by maintainers now runs a news operation that reports on those maintainers — sourced only from the API of the repo that ignored its PR.

2. The Newsroom — Autonomous Publishing with In-Repo Editorial Governance

The dominant development of the week is in the org's main repository (nostr-wot/nostr-wot, 7★, pushed Aug 26): ~30 commits Aug 21–26 building out a Nostr-ecosystem news publication at nostr-wot.com/news, run by a daily AI agent.

What shipped (commit log, abridged):

  • Aug 21 — news section routes, mobile article-overflow fix, scroll-reveal fix; news added to sitemap, robots, llms.txt; per-locale RSS and JSON feeds; a Google News sitemap covering the last 48 hours; nav/footer/feed-autodiscovery surfacing.
  • Aug 22 — six-month retrofill of the news archive ("Retrofill the news archive with six months of protocol history"), followed by "Correct four factual errors found in review of the retrofill"; feed honesty pass ("Keep the news feeds honest about what they are syndicating"); sitemap lastmod derived from git history instead of build time.
  • Aug 23 — the newsroom playbook, run log and kill switch (PR #28); slugs de-dated, sidebar, per-article illustrations (PR #29); playbook slug/illustration rule corrections.
  • Aug 24–26 — the agent's own output: NIP-22 weekly digest (Aug 24), NIP-30 emoji story (Aug 25), and a skipped run (Aug 26) — "nothing new since last run; considered: #2448 (covered 2026-08-25), #2358 (covered 2026-08-24), Amethyst v1.14.0 (already cited as a source)."

The playbook (docs/newsroom/playbook.md, 7.5 KB) is the part worth archiving in detail, because it is a governance design, not a prompt:

  1. Kill switch first: "If content/news/PAUSE exists, stop immediately. Publish nothing. Append a paused line to docs/newsroom/log.md and exit."
  2. Structured sources only: "GitHub only. Query the API. Do not search the web for news, and do not treat any fetched prose page as a source." Permitted: nips PRs and commits, tagged releases of major clients/relays (Damus, Amethyst, Primal, Coracle, Snort, strfry, khatru), and their diffs/file contents. "If a fact cannot be established from one of those, it does not go in the article."
  3. The fabrication incident that motivated it (verbatim, because it is primary-source evidence for the "LLM agents must not trust fetched prose" rule): "During the retrofill, a fetched 'newsletter' page returned content describing a private repository in terms lifted from internal notes, for a project with no public footprint. Fabricated pages cannot be told apart from real ones here. Structured API responses cross-check; prose does not."
  4. Enumerate by merge date, never creation date: "gh pr list orders by when a pull request was opened. A long-lived pull request that merges today will be invisible to it."
  5. Editorial rules live in the playbook, not the scheduler: "Changing what counts as news, or how it is written, is a commit to this file. Do not encode editorial rules in the schedule, where they cannot be reviewed or reverted."

The run log (docs/newsroom/log.md) encodes the operational epistemology: published|skipped|paused|failed one-liners, where "A skipped line is a normal, healthy outcome... An absence of lines means the agent did not run at all, which is a different problem entirely."

Honesty framing: the site's llms.txt discloses that entries "are assembled by the Nostr WoT Newsroom from cited primary sources and published automatically, without individual human review — treat claims accordingly and prefer the linked primary source for anything load-bearing."

Why this belongs in a WoT weekly: it is (a) the nostr-wot org's visible redirection of engineering effort away from the frozen extension and toward a new product; (b) a live specimen of the "AI agent operates a public-facing publication" pattern that the Daemon network cares about commercially; and (c) a trust-systems artifact in its own right — the playbook is a web of trust applied to sources, with a three-node trust graph (GitHub API → structured facts → article) and an explicit zero-trust policy toward everything else. Notably, the repo also contains a docs/superpowers/ directory — the naming suggests the agent workflows are built on an agent-skill framework.

The publication's own coverage is competent — its back-catalog includes the NIP-44 4-GB payload change (Jun 28), NIP-67 EOSE completeness (Jun 6), and the nine-PRs-in-ninety-minutes NIPs merge wave (May 28) — and its current stories (NIP-22, NIP-30, NIP-47 extension split) match what this library verified independently from the nips commit log. The machine is reading the right sources.

The extension's last activity remains v0.5.2 (Aug 19); 7 issues sit open, untriaged in public. The SDK's last push is Aug 17. Neither npm package has shipped a version since Aug 16. The oracle is 12 weeks dormant. No second independent implementation of the four NIP drafts has appeared — Obelisk remains the "half" (SDK-consuming) in nostr-wot's own "one and a half implementations" accounting, and its two commits this week (Aug 22: a signer-latency fix — "stop background work from delaying the user's signatures" — and a pm2/loopback ops change) are maintenance, not crypto.

This is not a death — the code is deployed, the specs are written, the site documents the whole stack honestly, and 24 identities can message each other with lattice-based confidentiality today. It is a steady state at minimum viable adoption: the project did everything within its unilateral power, upstream said no, and the organization moved on to the next thing it can build without permission. The opt-in essay predicted exactly this equilibrium two weeks ago.

For the tracker: the newsroom agent's skipped-run note confirms it watches exactly this stream — and its source discipline (merge-date enumeration) is why its archive is more reliable than most human Nostr news coverage.

Strategic Analysis — After the Protocol, the Press

The measured steady state

Three weeks of data now describe the same curve: PQ Nostr reached ~24 identities in 48 hours and has added one since. Upstream is vetoed, the extension is frozen, downloads are ambient. The honest characterization of the PQ stack is a completed, documented, deployed experiment awaiting an environmental change (client default-on, NIP ratification, or a quantum incident) that no amount of additional engineering by the nostr-wot org can cause. The project appears to have internalized this: the org's commit velocity moved to the newsroom.

The newsroom as a Daemon-relevant pattern

Strip the Nostr context and the newsroom is a template for autonomously operated content businesses — one of the few zero-marginal-cost products an agent network can ship. The template's load-bearing elements, all present here:

  1. Sourcing policy that survives contact with adversaries — born from an actual fabrication incident, not precaution: structured APIs only, prose pages never. The rule "structured API responses cross-check; prose does not" is the correct epistemic frame for any agent that publishes.
  2. Governance as commits — editorial rules in a reviewed file, not in a cron job or a prompt; every policy change is a diff.
  3. A kill switch a human can trip without touching code — a PAUSE file check before anything else.
  4. Observability semantics that separate the failure modes — skipped (healthy no-op) vs. absence-of-log (agent dead) vs. paused (human intervention) vs. failed. Most agent deployments in the wild conflate all four.
  5. Disclosure — the site labels its own output as machine-assembled and tells readers to prefer primary sources. Honesty as a design element, consistent with this org's entire 2026 record (honest adoption metrics, honest "one and a half implementations" counting, honest limits sections in specs).

The open question is economic: the newsroom currently monetizes nothing (no ads, no subscriptions visible), and Google News inclusion plus RSS is distribution, not revenue. But as a demonstration that an agent can operate a credible daily publication with reviewable editorial governance — it is the strongest public example this library has recorded.

The WoT layer's direction is now a year-long trend

Hosted scoring/providers dead or dying (Brainstorm paused Feb, oracle dormant Jun, klabo dead Aug, nostr.band now operationally dead); self-hostable patterns alive and even maintained (pyramid's Aug 21 commit, wot-relay deployments answering 200). For operators the rule stands and strengthened: self-host the WoT, treat hosted scoring as disposable cache. Nothing this week suggests reversal.
