The fixed-section differences between betas track the rotation pipeline itself:

Katzenpost — The Largest Single-PR Week in Project History (#1206, #1213, #1214 Landed Oct 7–8)

The Katzenpost server has been hardening continuously since the Sep 27 #1133 NoOp gateway heartbeat. The week of Oct 7–8 lands three merged security-hardening PRs at once, with Jacob Appelbaum as the dominant author:

#1206 (Oct 7, merged) — authority/voting: dirauth fixes and consensus reliability merges forty-four branches in order, each a "failing test → fix" pair. Wire/consensus/on-disk formats are unchanged (so existing nodes don't need to upgrade in lockstep). Two behaviour changes:

This is the dirauth layer getting the same "test-first, fix-second" treatment the relay layer got in #1182 — exactly the pattern ioerror asked for in Sep 27's CI hardening sweep.

#1213 (Oct 7, merged) — security: wipe dropped secrets, bound the thin-client listener, keep identifiers out of logs ships eight sub-fixes, each a branch, all "failing test first":

  • core/wire: wipe the session cipher states on Close
  • replica: wipe envelope private keys when they are dropped
  • client: bound thin-client reads, allocations, and connections
  • client, courier/server, replica: wipe ephemeral MKEM keys at their last use
  • client: wipe a SURB key wherever it is dropped
  • client: drop the blinding factor from a log line

#1214 (Oct 8, merged) — dirauth: reject late votes past reveal, bound topology layers, and guard mix slots is the "Byzantine-proofing" PR — three fixes:

  1. Late-vote SRV grinding prevention — once the authority has transitioned to stateAcceptReveal/stateAcceptCert/stateAcceptSignature, reject subsequent votes with commands.VoteTooLate; a vote carries the voter's SharedRandom commit, and accepting commits after honest authorities have already revealed their secrets lets Byzantine authorities grind the resulting SharedRandom.
  2. Bounded topology layers against prior consensus — generateTopology bounds layers against the prior consensus, preventing unbounded growth between epochs.
  3. Pinned-authority-only peer slot identity binding — mix peer slots are not keyed to an unpinned (outside-the-pinned-set) identity; peer-slot identity binding is restricted to pinned authorities; red-team-tested with a regression test.

#1215 (Oct 8, merged) closes the cluster — courier, server, client: nil guards on reply dispatch, session credentials error handling, .... Eight further PRs remain open (#1208 kaetzchen + courier re-dispatch pacing, #1209 client socks5 panic + ARQ jitter + bandwidth estimate + ping per-epoch + retryable-pigeonhole-not-ready, #1210 optional descriptor fields + client notice + service delay, #1211 cborplugin host-chosen socket + drain + geometry + parameters, #1217 docker/quic transport pick + QUIC keepalives + cached read success, #1220 descriptor uploads bound to session link key + per-identity slots for pinned nodes, #1221 kpclientd systemd socket activation, #1219 in flight). HOPR — GNO-805 Channel-Balance Incident Trilogy (Oct 6–7) Closes

The GNO-805 ticket tracks a single incident where a payment channel drains below one-ticket face value, the path still gets selected, and the first-hop ticket fails in hopr-ticket-manager with balance of channel is too low, stalling traffic while the node still reads healthy. The fix is sequenced: #8485 chain/ticket-redemption → #8487 path/fund-check → #8486 transport/cold-1-hop-burst — the chain event is the upstream cause, the path selection is the surfaced-but-still-wrong layer above it, and the transport edge-fall is a sibling symptom.

#8485 (Oct 6–7) fix(chain): update the channel graph balance on ticket redemption (GNO-805) — ChainEvent::TicketRedeemed (post-redemption ChannelEntry) was falling through process_chain_events's catch-all (which only records the graph edge balance for ChannelOpened/Closed/BalanceIncreased/BalanceDecreased). The routing graph kept each channel's funded balance on ticket redemption events — that funded balance didn't reflect drained ticket value, so paths selected routes that would fail at ticket-manager.

#8487 (Oct 7) fix(path): fund-check the extended search against the finished path length (GNO-805) — Phase 1 of path selection (EdgeValueFn::forward) rejects the drained first hop correctly; Phase 2, the extended forward search (compute_extended_forward_paths), used the traversal depth (shorter_length) instead — so a path that finishes with a drained first hop was passed through.

#8486 (Oct 7) fix(transport): keep a cold 1-hop burst from losing its route at a counter flush — Score only settled packets. A cold burst on a fresh 1-hop Session lost its route for 5 seconds when its first packets were still in flight at a counter flush (master counterpart of release/4.0 backport #8488).

Plus ##8478 (Oct 6) fix(session)!: decouple the PIX recovery floor and quota from the HOPR payload size (closes #8469): the PIX max_recovery_time floor was 1.5 Mbps / HoprPacket::PAYLOAD_SIZE, so Sep 29 #8313's payload change (1038 → 3246 B) silently tripled it and hoprd refused valid profiles at load. ASSUMED_SESSION_PACKET_RATE → MAX_ASSUMED_SESSION_PACKET_RATE (fixed 5000 packets/s upper bound ≈ 58 Mbps of Session data); deadline judged by fill.max_rate counted up to that bound.

#8472 (Oct 5, closed/merged) — share-bearing SURBs first in the Exit SURB store (LIFO is wrong because SURBs are produced with share-bearing first); #8473 (Oct 5, closed/merged) — feat(protocol)!: count lost PIX shares exactly and drop the LIFO SURB pop order. Companion diagnostic #8490 (Oct 8, merged) test(session): reproduce the balancer estimate-pin and output collapse under return-path loss.

HOPR is shipping real bug fixes fast ahead of the 4.x stable cut. The Sep 23 surface-area code (PIX supervision #8237, parameterized admission #8377, 1956609/9766 SURB-buffer gauge #8440) plus the Oct 1 stalled-sink (#8463) + return-path visibility (#8464) + breaking-field-extensions (#8313/#8460) + Oct 5–8 GNO-805 incident trilogy is a coherent hardening arc: separate the diagnostic, the protocol change, and the incident repair into distinct PRs that each close one ticket.

Research / EPrint Sweep (Oct 2 → Oct 9)

The IACR ePrint listing for /2026/ was parsed; keyword filter (anon|mix|onion|traffic|oblivious|censor|stegan|relay|dissent|sybil|fragment|pir) returned four in-window mixnet/PIR/anonymity papers:

ePrint 2026/2334 (Oct 4) — Trapdoor Projective Sampling and Identity-Based Anonymous Broadcast

"In anonymous broadcast encryption, a ciphertext hides both the message and the set of recipients. ... Kiayias–Samari lower bound forces the ciphertext to grow linearly with the number of recipients. ... The bounded universe is the setting where anonymous broadcast becomes concise, even asymptotically optimal ... Far from a mere restriction, it is the building block for anamorphic communication against a dictator ... DPPY is, however, secret-key anamorphic encryption ... a public-key variant does not suffice against a strong adversary, since a per-recipient public key lets a dictator ask for the matching secret key. This motivates hiding identities directly, with no recipient public key published, leading to identity-based anonymous broadcast in the bounded model ... projective sampling (Ling, Phan, Stehlé and Steinfeld, LPSS, CRYPTO '14), the tool underlying concise anonymous broadcast encryption, offers no key extraction: private keys cannot be produced from a projected key fixed in advance. We introduce trapdoor projective sampling that reverses ..."

Why this matters for Nym / Katzenpost / Sphinx Packet Format: bounded-universe anonymous broadcast is the cryptographic primitive that turns loopix's "send SURB to a node, get reply" into "send to N rotating receivers, the dictator learns nothing about which subset". The same machinery would let a Nym-style mixnet offer bounded-anonymity-set ephemeral channels.

ePrint 2026/2369 (Oct 6) — StOMR: Stateful Oblivious Message Retrieval

"Oblivious Message Retrieval (OMR) enables recipients to retrieve messages from an untrusted server without revealing which messages correspond to them ... Existing constructions are inherently built in the public-key setting and use Fully Homomorphic Encryption (FHE) to allow a detector to scan a public bulletin board and produce a compact encrypted digest ... sender-published signals are large (hundreds of kilobytes), leading to significant bandwidth, storage, and on-chain costs. In this work, we explore the efficiency gains achievable by moving to a private, stateful setting, and introduce stateful OMR, a new model in which senders and receivers maintain lightweight private state to enable more efficient anonymous communication. Based on this model, we design StOMR, a protocol that significantly reduces the size of sender signals compared to prior approaches. To support the required shared state, we further introduce an OMR Key Encapsulation Mechanism (OMR-KEM), which allows users to privately establish shared state and instantiate stateful OMR without out-of-band channels. We implement StOMR in C++ and evaluate it against the state-of-the-art systems PerfOMR (USENIX Security '24), SophOMR (USENIX Security '25) ..."

The OMR-KEM primitive is independent of the mixnet framing; what's interesting here is the stateful shift: senders and receivers carry state, sender signals drop to compact. For Nym's SURB reply chain, the stateful OMR pattern would be a layer below the SURB — a noise floor below which the reply becomes a pull, not a push.

ePrint 2026/2385 (Oct 6) — SkrrtPIR: Doubly-Stateless Batch PIR from Single-Key RLWE Unpacking

"Batch Private Information Retrieval (Batch PIR) allows a client to privately retrieve multiple entries from a public database while amortizing query costs. However, concretely efficient schemes typically rely on per-client server state, such as client-specific evaluation keys ... we initiate the study of doubly-stateless Batch PIR, where the server stores no per-client state and the client maintains no database-dependent hint. ... The core technical ingredient is a single-key RLWE unpacking procedure that replaces the traditional tree-based approach, which requires logarithmically many Galois keys, with a linear walk over a cyclic Galois subgroup requiring only a single Galois key."

The doubly-stateless requirement is exactly what NymHS would want for a mixnet-resident PIR layer — the PIR server has no incentive to keep per-client state, and the client can roam across Nym exit gateways without re-issuing evaluation keys.

ePrint 2026/2397 (Oct 7) — Hashing Beats Trees: Practical Oblivious Dictionaries in SGX

"Oblivious RAM (ORAM) is a powerful cryptographic primitive that hides both the contents of outsourced data and the access pattern ... we show this trade-off [over Path ORAM tree traversal at Θ(log n)] to be suboptimal ... With low position map cost, probabilistic hash tables prevail as dictionary data structures due to their small, constant number of accesses compared to Θ(log n) path traversal ... We implement and analyze oblivious, probabilistic hash tables over Path ORAM, including several different strategies: chaining, power-of-two-choices, stash-less cuckoo, and de-amortized cuckoo hashing. Execution of these algorithms within a secure enclave requires 'double obliviousness', which in turn needs strict concrete maximum cost limits for each access ..."

The mixnet angle: this is the ORAM dictionary that an SGX-backed Sphinx routing-table lookup needs — and Nym's sphinx 0.8.0 + sphinx 0.8.0 V2 repliable messages (Oct 1) use a much smaller per-packet routing table on the gateway than the older Sphinx chain. ORAM dictionaries inside the SGX enclave let the routing table be credential-isolated from the mixnet operator's view of which key just looked up which destination.
