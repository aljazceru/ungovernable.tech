The Week in Detail

HOPR — Piz Palü v5.0.0 Stable Ships Oct 13 + PIX/Curvy Partnership Oct 14 + HOPR API v4.4.0 + HOPR Docs v5.0.0

HOPR Piz Palü is the major release that:

  1. "Opens node running to everyone" — the Network Registry NFT model that required an early-access NFT for the prior Dufour/Monte Rosa releases is discontinued in Piz Palü, replacing prior boost-NFT mechanisms with a flat-stake model.
  2. "Prepares the network for @Gnosis_VPN launching in Q4 2026" — Piz Palü is the protocol-layer cut that lands before Gnosis VPN (a privacy-first consumer VPN that runs over the HOPR mixnet) goes live.
  3. Restructures cover traffic — "Cover traffic has changed to reflect this: incentivized cover traffic" (the @hoprnet tweet thread). The Cover Traffic docs and the Tickets and Payment Channels docs are both tagged v5.0.0, meaning the economic model is the change, not the protocol primitive.
  4. Dufour migration story — the HOPR AMA on X (Oct 16) addresses migration from Dufour, including a new Safe, node module and wxHOPR transfer (so existing node runners migrate their bonded wxHOPR + bond from a Dufour account/operator-Safe to the Piz Palü structure).

HOPR v5 measurement-driven relay selection (Oct 13, 11h) — "HOPR v5 introduces a major change to how nodes select relays. Instead of simply checking who's online, the network now measures how reliably and quickly packets move through it." This is the relay-selection algorithm shift that anonset/Monte Rosa-tunable nodes have been waiting for: a node that lets a malformed packet queue behind its ack-acks scores low, whereas Dufour-era relay selection rewarded any node that simply responded. Operator implications: nodes need a healthy ack rate, not just uptime.

Curvy Protocol partnership, Oct 14 — "A privacy network can hide your traffic and still leak who paid for it. That leak usually happens on day one, when funds enter the system. We've been working with @Gnosis_VPN and @hoprnet to close it inside PIX." The technical deep-dive explains how PIX rewards exit operators for delivering traffic, while @0xCurvy keeps those payments unlinkable on-chain — the Gnosis-VPN-payment-path is the first consumer-grade use case for PIX payments.

HOPR API v4.4.0 (Oct 13, 18:39 UTC, release tag 7575071) ships in lockstep with the protocol — the hopr-api is the JavaScript library HOPR apps integrate against, so a stable hoprnet → a stable API.

HOPR docs versioning — Cover Traffic page now v5.0.0, Tickets & Payment Channels page now v5.0.0. The docs survive the major-version cut, meaning the documentation surface is itself a stable reference for the v5 model.

Standing-watch items closed this week:

  • HOPR 4.x stable — superseded by Piz Palü (v5.0.0) rather than 4.x being the stable cut. The open-source release/4.0 branch backports (e.g. #8488 4.0-backport of #8486) remain available for operators still on Dufour.
  • Gnosis VPN launch — now concrete Q4 2026 with the PIX/Curvy payment unlinkability concrete.
  • PIX supervision (#8237) — now in production as Piz Palü's incentive surface.
  • GNO-805 channel-balance incident trilogy (#8485/#8487/#8486) — closes last week and is carried into Piz Palü as the relay-selection economic basis.

Katzenpost — #1207–#1235 Cluster (Oct 9–14)

W42 extends the #1206/#1213/#1214 W41 hardening cluster with eight more merged security/correctness PRs (Oct 9–11), then a clean Convergence cluster (Oct 12–14), then packaging/release PRs (Oct 14). The trajectory is "harden the protocol → plumb the transport → bump the deps → tag the release".

Oct 9–11 — the W41 backlog merges

  • #1207 (Oct 9) server: mix key replay filter, first boot link key, log level, channel gauges — mix keys gain a replay filter (re-discovery of a previously-seen mix key is rejected rather than re-accepted); first boot generates a first-boot link key that wraps the first session; log level to info reduces what lands in operator logs (privacy default); channel gauges expose per-channel counters via prometheus-style metrics.
  • #1208 (Oct 9) server, courier: kaetzchen fixes and courier re-dispatch pacing — kaetzchen (mixnet-side auto-responder services) drop errors are now gauge-paired; courier re-dispatch is paced (not "as fast as the worker can fire").
  • #1209 (Oct 9–10) client: socks5 panic, ARQ jitter, bandwidth estimate, ping per epoch, retryable pigeonhole-not-ready — five sub-fixes: a SOCKS5 client panic that could crash the client when a pending request was reaped, ARQ (automatic repeat request) jitter to spread retransmissions, a bandwidth estimate in the client that surfaces for the operator, ping-per-epoch (one ping per consensus epoch rather than per request), and retryable pigeonhole-not-ready (the client no longer treats "pigeonhole service not yet up" as fatal).
  • #1210 (Oct 10) core/pki, authority/voting, server: optional descriptor fields, client notice, service delay — descriptor fields are now optional (descriptors can omit fields the operator doesn't run); clients receive a notice when the PKI publishes a change that affects them; service delay is the new server config knob (delay before service starts so the server doesn't accept connections before the PKI considers it "ready").
  • #1211 (Oct 10–11) server/cborplugin, courier: host-chosen plugin socket, host geometry, plugin parameters — the cborplugin transport layer now supports host-chosen plugin sockets (the host, not the plugin, picks the socket path), host-chosen geometry (the host, not the plugin, picks the Sphinx-packet geometry), plugin parameters (the host can configure the plugin at spawn time). This is the protocol-level plumbing that lets one katzenpost host run plugin servers with different parameter profiles.
  • #1217 (Oct 11) docker, quic, courier: pick the testnet transport, keep QUIC links alive, serve a cached read success — the testnet transport is selectable from the docker image; QUIC keepalives keep idle QUIC links from being silently dropped; cached read success is the new courier endpoint (a reader can hit a cache and fall back to the chain).
  • #1220 (Oct 11) authority: bind descriptor uploads to the session link key; per-identity slots for pinned nodes — authority-side descriptor uploads are now bound to the session's link key (an upload that comes in on one session can't be re-played on another) — per-identity slots for pinned nodes (each pinned node gets its own slot, so one node can't fill another's quota).
  • #1221 (Oct 11) kpclientd: systemd socket activation — the kpclientd (Katzenpost client daemon) now supports systemd socket activation — meaning systemd can hold the listening socket and kpclientd can be brought up lazily when the first connection arrives, then torn down when idle. This is the "run-anywhere mixnet" hook that operators have been asking for since Mix Networks 2026 Research and Deployment Tracker noted the kpclientd bottleneck in late W41.

Oct 12–14 — Convergence Cluster

  • #1222 (Oct 11–12) server/service: halt predelay before worker, drain readyCh on shutdown, and guard releaseDelayed — server starts the predelay timer before the worker goroutine starts so a slow worker doesn't get free admission; on shutdown readyCh is drained so a worker that received "stop" doesn't miss the close; releaseDelayed guard prevents a delayed release from being released twice.
  • #1223 (Oct 12) server/service: halt predelay before worker, drain readyCh on shutdown, and guard releaseDelayed (same as #1222; separate small PR or rebase — to be clarified). #1224 (Oct 12) go.mod, ci: update go to 1.26.9, x/net to v0.61.0, and check-latest Go — go.mod pins go 1.26.9 (the chain's first 1.26.9-stable pin), golang.org/x/net to v0.61.0 (off the v0.51.0 of late W41), and CI checks for the latest Go at build time.
  • #1225 (Oct 12) docker, ci, genconfig: match namenlos with KYBER768-X25519 on the wire — Kyber768-X25519 is the wire-level hybrid that the "namenlos" (nameless) configuration now advertises in CI; mismatches between CI config and genconfig are resolved.
  • #1226 (Oct 12) QUIC: transport fixes, pinned keys, options, metrics and a QUIC testnet — 21-commit series. This is the QUIC transport getting the same consensus-grade convergence that the dirauth layer got in #1206: pinned keys (the QUIC TLS key is bound to a known pubkey, preventing on-path MITM), options (the QUIC connection-options knob), metrics, and a QUIC testnet. The QUIC testnet is the docker/genconfig-driven testnet that means a future Test-Net-style deployment can talk QUIC between mix nodes.
  • #1227 (Oct 13) Update highctidh to v1.0.2026101300 — CTIDH PQ-NIKE library refresh to the 2026-10-13 cut; CTIDH is the katzenpost-quoted isogeny-based NIKE, used in CTIDH512-X25519, CTIDH1024-X25519, and the X448 hybrids.
  • #1228 (Oct 13) Update hpqc to v0.0.93 — HPQC (the katzenpost PQ-crypto library) version pin.
  • #1229 (Oct 13–14) Pre-release fixes: testnet, ping and motd, plugins, authority uploads, proxy bounds — four-commit pre-release sweep. The testnet uses the new QUIC transport; ping and motd are now consistent (motd = "message of the day", the PKI-published status line); plugins; authority uploads (cleaner descriptor upload path); proxy bounds (the thin-client proxy now has memory/CPU bounds).

A concrete in-window client-PR cluster that's relevant to Mix Networks:

  • Auto selection no longer treats US states as separate jurisdictions (the v2026.13.0 fix above). The bug: a US-state geo-exclusion routed one US state's exit differently from another, producing a per-state path that an adversary observer could fingerprint. The fix: jurisdiction is now country-only — same vector as the longer Nym Wiki discussion of jurisdiction-based fingerprinting.
  • six_months subscription kind (#6320) — six-month plans now have a clean UI path. The trend is Nym's plan-economics model moving toward longer-cycle plans, matching the nym.com/nymvpn-roadmap "v2026.13: Profiles + QR codes + Geo Exclusion" goals.

The Banner Story (in One Paragraph)

HOPR ships Piz Palü (v5.0.0 stable, Oct 13) — the only major-version cut across the mixnet space in five months. Piz Palü opens node running to everyone (no more Network Registry NFT requirement), prepares the network for @Gnosis_VPN launching in Q4 2026 (Piz Palü is the cut immediately before the consumer-VPN launch), restructures cover traffic to incentivize cover-traffic-node operation rather than only rewarding relay packets by funds, and replaces the relay-selection algorithm from "who's online" to "who delivers packets reliably and fast". Three other projects landed coordinated-but-routine hardening in the same window: Nym v2026.20-glasgow (Oct 13 binaries) adds passphrase-encrypted client keys + optional pemstore encryption as the productionization surface for enterprise operators, plus an important sphinx-key rotation race fix (#7212) and an explicit ring crypto provider (#7211); Tor 0.4.9.14 + Tor Browser 15.0.25 + Tails 7.15 (Oct 8/9 → 12/13) ships a high-severity security triple affecting all four roles — the Windows code-signing cert workaround first applied on Sep 1 is finally retired in TBB 15.0.25's build; Katzenpost lands #1207–#1235 over Oct 9–14 — the QUIC testnet (#1226) is the long-promised convergence of the docker/QUIC transport work that landed in pieces over Sep 27 → Oct 8, and #1221 brings kpclientd systemd socket activation to source (the "run-anywhere mixnet" hook).
