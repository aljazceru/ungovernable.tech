2. ePrint 2026/2137 — single-trace ML-KEM key-recovery (Sept 21)

Authors: Vahid Jahandideh, Radboud University Nijmegen. URL: eprint.iacr.org/2026/2137

The paper demonstrates that the CBD (centered binomial distribution) sampler used in ML-KEM key generation — which produces coefficients with small Hamming weight (k=2 for ML-KEM-512/768, k=3 for ML-KEM-1024) — leaks enough per-coefficient information in a single power/EM trace that an adversary can recover the secret.

Why this is exploitable: a coefficient with k=2 can only take values in {-2, -1, 0, 1, 2}. The small domain means a single side-channel sample has high signal-to-noise against the noise floor of the measurement, even with practical leakage bandwidths.

The countermeasure (q-randomization): store each coefficient as v + r·q with random nonzero r, so the NTT and downstream code run unchanged but the measurement sees r·q + v instead of v. The randomization drives the sign-leakage to the noise floor (the random r dominates the Hamming-weight signal) and reduces the NTT magnitude leakage by 4.5×. Concretely: the lattice attack block size rises from 129 back to 611 — about 4 bits of estimated security lost instead of more than 140.

Cost of the countermeasure: 937 bytes of additional firmware.

Important boundary: this is not a break of the ML-KEM primitive. It is an implementation-hardening result — the standard FIPS 203 implementations (liboqs, AWS-LC, mlkem-native, OpenSSL via oqs-provider) do not include q-randomization in their reference code paths; an operator concerned about side-channel attacks on key generation (e.g., HSM vendor, embedded TLS implementer) needs to evaluate whether to adopt the countermeasure.

For the freedom-tech stack: most freedom-tech deployments use TLS via OpenSSL / Go / Rust / NSS; key generation is in the cryptographic library, and the libraries have not (yet) integrated this countermeasure. The risk is most acute for embedded systems where power-side-channel attacks are practical (smart cards, IoT, mobile devices with JTAG exposure). Server-side ML-KEM key generation in OpenSSL/AWS-LC is generally considered side-channel-safe by design (constant-time sampling), but the paper shows that even constant-time sampling may leak the small-domain signal — a subtler attack class than the standard side-channel literature addresses.

3. ePrint 2026/2131 — 1024-bit RSA forgery in nearly SNFS time (Sept 20)

Authors: Laura Shea, Miro Haller, Adam Suhl, Nadia Heninger (UC San Diego); Emmanuel Thomé (INRIA Nancy). URL: eprint.iacr.org/2026/2131

The paper shows that the conventional RSA security estimates (based on GNFS / general number field sieve complexity for factoring) underestimate the concrete security cost for the signing-key structure. With a signing oracle (an adversary who can induce RSA signing operations), the SNFS (special number field sieve) applies to the signing-key parameters, yielding attack costs 15–30 bits lower than factoring-based estimates for RSA-1024 through RSA-4096.

The headline result: even RSA-4096 does not appear to meet a 128-bit security level in this attack model.

Important boundary: this is a with-signing-oracle attack. The adversary model assumes the attacker can submit chosen messages and observe signatures. Without an oracle, factoring-based security estimates still apply (modulo the standard cryptographic caveats about parameter generation, side channels, and implementation bugs). The paper's contribution is to show that the conventional factoring-based estimates systematically under-count the worst-case signing-key attack cost.

The authors' framing: "This highlights a gap in current RSA-type security assumptions, and gives classical cryptanalytic evidence in favor of moving away from RSA entirely during the current post-quantum transition." This is a notable rhetorical move — cryptanalytic results traditionally stay neutral on operational guidance, and the choice to frame this as "evidence for moving away from RSA" reflects the broader community consensus that the post-quantum transition is happening regardless of the quantum threat timeline.

For the freedom-tech stack: RSA-2048 and RSA-4096 remain ubiquitous in (a) TLS server certificates, (b) SSH host keys, (c) S/MIME email, (d) DNSSEC, (e) code signing (rare but persistent). The paper's contribution is to harden the case against continued RSA dependence in long-lived signing keys. ML-DSA-65 (FIPS 204) at 1,952-byte public key / 3,309-byte signature is the structural replacement; hybrid Ed25519+ML-DSA-65 is the conservative path. Cross-reference ML-DSA and Hybrid KEM Migration.

4. The freenode synthesis — McEliece parameter debate reactivated (Sept 25)

The Sept 25 freenode.net article is a synthesis of pqc-forum discussion, not a new cryptanalytic event. The two underlying events are:

(a) HAWK withdrawal — July 29, 2026 (not new news). Steve Weis (Anthropic) announced an improved key-recovery attack against HAWK-n that reduces to SVP in dimension n/2+1 (paper at eprint.iacr.org/2026/1593 and anthropic.com/document/hawk_key_recovery.pdf). Concretely: - HAWK-512 gate count drops from 2^150 to 2^108 (AGPS'20 model) - HAWK-1024 gate count drops from 2^288 to 2^182 - HAWK-256 was broken end-to-end in a few hours on one server - Weis was explicit: "This result does not impact Falcon, ML-DSA, or other lattice-based schemes." - The work was found by Claude "with minimal technical guidance from people" - Daniel Apon independently verified: "Nice. It checks out independently for me." - The HAWK team helped verify; withdrawal from the NIST process followed on July 29, 2026

(b) Classic McEliece quasipolynomial cryptanalysis — Aug 10, 2026 (not new news). Ghoshal/Ishai/Jain/Sun, eprint 2026/1630: a provable quasipolynomial-time distinguisher of Classic McEliece public keys from random bytes, plus a heuristic quasipolynomial decryption algorithm. The claimed complexity is below security level 1 for all parameter sets proposed by the Classic McEliece team.

What's new in the Sept 25 synthesis is the pqc-forum engagement: - Demi Marie Obenour (highlighted the McEliece paper on the forum): "The attack is currently impractical, but if it works, it seems quite devastating for Classic McEliece and for Goppa McEliece in general." Restoring margins would drive ciphertext sizes toward quadratic growth in the security parameter. Asked whether the scheme would retain any advantage over HQC or BIKE at that size. - Christopher Peikert (forum): noted claims on the order of 2^102 bit operations against Category 3 and 5 sets previously advertised near 2^207 and 2^272, asked whether it was "fair to claim that Classic McEliece is broken" for those parameters. - D. J. Bernstein (challenged naive bit-operation tallies): argued that the practical bottleneck is generating and routing ~2^93 bits across large RAM fabrics, and that hardware price-performance for long-distance routing is far worse than the pure gate model suggests. The exchange shifted the argument into cost models, memory hierarchies, and whether inflated parameters remain competitive once public keys move into the multi-megabyte range. - Steve Weis posted corrected tables and parameter examples showing how far (n, t) pairs must be stretched before the attacks sit behind 2^192 or 2^256 — with corresponding public-key blow-ups. - John Mattsson (Ericsson): cautioned against presenting FrodoKEM as the default conservative choice given thinner deployment and scrutiny than ML-KEM, and recommended an ML-KEM + HQC hybrid for diversification across hardness assumptions and better performance than FrodoKEM alone. - Bas Westerbaan (Cloudflare): answered with adoption graphs illustrating how uneven post-quantum uptake already is across human-driven and automated clients. - Obenour (operational): "One doesn't have to wait for a scheme to be standardized before deploying it." Cited OpenSSH shipping Streamlined NTRU Prime before ML-KEM was finalized as FIPS 203. For bandwidth-constrained settings (Ericsson links where only isogeny-based options fit), suggested operators who control both ends can field research constructions like MIKE, hybridized with ECDH and Kerberos-style symmetric keying, so that security holds if any component holds.

For freedom-tech: the substantive takeaway is ML-KEM + HQC hybrid is now the most explicitly-named diversification strategy on the standards track (per Mattsson's direct recommendation). The HQC KEM is the alternate KEM NIST selected for standardization in 2025; HQC standardization is expected 2026-2027 (per HQC). The hybrid ML-KEM-768 + HQC-128 combination provides diversification against the lattice-only assumption of ML-KEM while preserving performance within ~2× of pure ML-KEM. FrodoKEM is explicitly not the conservative default (per Mattsson); MIKE (isogeny-based, research-grade) can be fielded in operator-controlled settings.

7. FIPS 206 (FN-DSA / Falcon) and the JOSE composite line

FIPS 206 status: unchanged. NIST submitted the draft for approval on 2025-08-28; the IPD has been under public comment since. The Google Groups pqc-forum thread on FIPS 206 status updates (groups.google.com/a/list.nist.gov/g/pqc-forum/c/1HXzjlMUU6Y) continues to accumulate feedback, including a recent thread on whether hedged signing should be preferred over plain randomized signing. No fresh public document from NIST in the September 19–25 window.

draft-ietf-jose-pq-composite-sigs-04 (Sept 11, Prabel/Sun/Gray/Reddy) is now ~14 days in queue. Still in WG Document state. The JOSE composite line is the active frontier for JWS/JWE PQ migration but is procedurally slow — no shepherd, no AD, no IANA review. Companion: draft-ietf-jose-pqc-kem-06 (Tschofenig/Reddy/Banerjee, JOSE WG, last updated 2026-07-06) cites FIPS 206 as upstream — unchanged.

draft-ietf-cose-falcon-04 expired 2026-09-16 per the IETF draft page. The COSE WG's FN-DSA document is now expired (no active revision). This is a maintenance concern — operators planning to cite the document should check whether a -05 has been uploaded since.

8. The September 25 freenode.net synthesis — what's actually new

The two articles published Sept 25 (ML-KEM TLS appeal and PQC timelines under pressure) are both syntheses of pqc-forum / standards-mailing-list discussion. They are useful because:

  1. They collect dispersed pqc-forum comments into a coherent narrative — Bernstein, Peikert, Mattsson, Westerbaan, Obenour, Apon are all quoted with specific operational positions.
  2. They identify the ML-KEM + HQC hybrid as the most explicitly-named diversification strategy on the standards track (Mattsson's recommendation).
  3. They surface the HAWK-256 end-to-end break in hours on a single server as a concrete demonstration of AI-assisted lattice cryptanalysis — the Anthropic/Weis result was published July 29 but the deployment-time implication ("lattice designs still outside the finalized set can lose security margin quickly, and AI assistance can shorten the path from design claim to concrete break") was not fully synthesized until Sept 25.
  4. They surface the operational distinction between "wait for standardization" and "deploy now if you control both endpoints" (Obenour's argument, with OpenSSH+NTRU Prime as precedent).

What they don't break: ML-KEM, ML-DSA, SLH-DSA, HQC, BIKE, FrodoKEM (the finalized or near-finalized schemes). The HAWK withdrawal removes one Round 3 signature candidate; the McEliece parameter debate threatens an alternate KEM that has not been formally selected. The operational recommendation set is: hybrid (RFC 10024) for TLS, hybrid Ed25519+ML-DSA-65 for high-value code signing, ML-KEM+HQC for diversification, SLH-DSA for conservative backup, MIKE for operator-controlled research-grade paths.

Operator checklist for the September 19–25 window

For a federal-contractor or vendor shipping PQ-relevant products: - [ ] RFC Editor re-hold: both draft-ietf-tls-mlkem and draft-ietf-tls-mldsa are Blocked under appeal as of 2026-09-24. Cover: HSM roadmap; TLS hybrid deployment; code-signing path; SSH PQ hybrid; long-term archive encryption; identity/PIV PQ plan. No change from prior weeks. - [ ] IETF-127 attendance (Nov 14–20, 49 days): LAMPS agenda should have composite-sigs published or imminent; PLANTS agenda should have MTC -06 advancing; TLS agenda likely delayed by the appeal dispute; JOSE agenda should have JOSE composite-sigs-04 advancing. - [ ] FIPS 206 final: still pending. No fresh NIST public document in this window. DigiCert's "wait until final" position holds. Operators planning around FN-DSA should have a fallback to ML-DSA-65.

For a freedom-tech deployer (independent of federal procurement): - [ ] No action items from the appeal: the KEM-then-compose architecture is the IETF's documented path; the dispute is about specific document publication, not about the cryptographic primitives. Continue deploying hybrid (RFC 10024 in TLS; mlkem768x25519 in SSH; Signal PQXDH in messaging; iMessage PQ3 in messaging; RFC 9980 hybrid in OpenPGP). - [ ] ML-KEM + HQC hybrid is now the most explicitly-named diversification strategy (per John Mattsson's Sept 25 pqc-forum post). For operators with the freedom to deploy non-finalized primitives, this is the standards-track-aligned diversification path. HQC standardization is expected 2026-2027; operators can field HQC hybrid before the standard finalizes. Cross-reference HQC. - [ ] ML-KEM key-generation side-channel: ePrint 2026/2137 shows CBD samples are vulnerable to single-trace attack. For embedded / side-channel-exposed deployments, the q-randomization countermeasure (937 bytes firmware) restores ~4 bits of security loss instead of >140. Not a primitive break; an implementation-hardening result. - [ ] RSA-4096 does not meet 128-bit security in the signing-oracle model (ePrint 2026/2131). Continue moving away from RSA for long-lived signing keys. Hybrid Ed25519+ML-DSA-65 per Hybrid KEM Migration; ML-DSA-65 alone for short-lived signing. - [ ] MIKE (isogeny-based, research-grade) can be fielded in operator-controlled settings where only isogeny-based options fit (per Obenour's Sept 25 forum post). Hybridize with ECDH and Kerberos-style symmetric keying so security holds if any component holds. - [ ] No action items on the Dihedral Coset line: the August 15 GRZ refutation stands; ML-KEM and ML-DSA are not moving.
